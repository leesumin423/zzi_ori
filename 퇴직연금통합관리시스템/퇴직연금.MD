# 🏦 퇴직연금 통합 관리 시스템 (Retirement Pension Dashboard)

금융기관별로 분산된 퇴직연금 운용 데이터(엑셀 양식)를 하나의 통합 JSON 데이터베이스로 변환하고, 웹 대시보드를 통해 실시간 자산 비중, 연도별 추이(YoY), 만기 구간 분포 및 개별 상품 상세내역을 직관적으로 시각화하는 자동화 솔루션입니다.

---

## 📌 자료 작성 기준 · 출처 · 수정 방법 (반드시 먼저 읽기)

### 자료 작성 기준
- 각 스냅샷은 **분기말/반기말/연말 등 특정 기준일**의 잔액을 나타내며, 기준일은 각 금융기관이 발급한 잔액증명서·운용현황보고서·상품명세서상의 평가금액을 근거로 원본 엑셀에 수기 취합한 것이다.
- 확정금리형 상품(GIC·정기예금·이율보증형보험 등)은 **동일 기관+동일 상품명+동일 만기일**이면 같은 계좌(롤오버되지 않은 건)로 간주하고, 이 경우 분기가 달라져도 금리가 바뀌면 안 된다 — 바뀌어 있다면 데이터 오류 가능성이 높다 (`app.js`의 `findRateAnomalies` 자동 점검 기능 참고).
- **2026.2Q(2026-06-30) 기준**은 2026-07-20에 회계팀 감사자료(은행별 원본 PDF, 아래 출처 참고)와 10개 기관 전 항목을 대사(對査)하여 검증 완료했다. 그 결과 발견된 4건의 오차(농협 한국투자증권ELB 만기일, KB국민은행 메리츠화재GIC 금액, iM뱅크 전북은행정기예금 최초가입일, 현대해상 GIC 금리·만기·금액)를 감사자료 기준으로 수정 반영했다. 다른 분기는 아직 감사자료 대사를 거치지 않았다.

### 값을 수정하려면 (다음 개발 시 참고)
1. **절대 `data.json`을 직접 고치지 않는다** — `parse_data.py`를 다시 돌리는 순간 되돌아간다.
2. 위 표에서 해당 기준일의 **원본 엑셀 파일**을 찾아 연다. 시트 안에서 구분(은행)·상품명으로 해당 행을 찾고, **E열=금리, F열=최초가입일, G열=만기일, H열=평가금액** 셀을 수정한다.
3. `python parse_data.py` 재실행 → `data.json`이 갱신된다.
4. 대시보드를 새로고침(F5)하면 반영된다.
5. **새 분기 데이터를 추가**하려면 `parse_data.py`의 `BASE_DATES` 딕셔너리에 `"YYYY-MM-DD": (파일경로, 시트명, 표시라벨)` 형태로 항목을 추가한다.

## 1. 어떤 문제를 해결했나

- **분산된 데이터의 취합 한계**: 농협, 산업은행, 우리은행, 기업은행 등 여러 금융기관에 쪼개져 있는 퇴직연금 데이터가 해마다 개별 시트 형식으로만 보관되어 전체 운용 규모와 가중평균 수익률을 파악하기 어려웠습니다.
- **수익률 산출 방식 일원화**: 원리금보장형(GIC, ELB/DLB, 정기예금)과 분기별 실적배당형(펀드) 상품의 수익률을 가중평균 방식으로 통합 계산하는 체계를 갖추어 실제 포트폴리오의 실적을 한눈에 비교할 수 있게 하였습니다.
- **만기 관리 누수 방지**: 특정 연도에 만기가 도래하는 고액 상품들을 놓치지 않도록 만기 도래 예정 목록 필터링 및 금융기관별 상세 조회를 가능케 하여 자산 재운용 전략 수립을 지원합니다.

## 3. 주요 기능 및 화면 구성

### ① KPI 핵심 지표 요약 카드
- **총 운용자산 규모**: 선택한 조회 기준일 시점의 총 연금 평가액 표기.
- **가중평균 수익률**: 실적배당형과 원리금 보장 상품의 비중을 가중하여 산출한 총 포트폴리오 수익률(%p 단위 전년 대비 추이 분석 포함).
- **연 예상 이자 수령액**: 정기적으로 유입되는 이자 소득을 정수 단위로 소수점 이하 반올림하여 직관적으로 노출.

### ② 금융기관별 & 상품유형별 자산 배분 (원형 도표)
- **Doughnut & Pie 차트**:
  - 각 조각의 라벨은 실제 각도(좌/우) 그대로 짧은 지시선으로 바로 옆에 표기하며, 같은 쪽에서 겹치는 라벨만 순서를 유지한 채 최소한으로 세로 이동시킨다(`smartOutsideLabels` 커스텀 플러그인, `app.js`). 텍스트 폭까지 실측해서 캔버스 밖으로 잘리지 않게 처리.
  - 비중 2% 미만 조각은 외곽 라벨을 생략(범례·툴팁으로 확인).
  - 범례는 **1열 커스텀 HTML 범례**로 표시(긴 상품명이 잘리지 않도록).
  - 기관별·상품유형별 차트 모두 특정 영역(조각/범례)을 클릭하면 아래 '상세 내역 테이블'이 자동 필터링(Drill-down)되며, 두 필터는 동시에 걸리지 않고 하나를 선택하면 다른 하나는 자동 해제됨.

### ③ 만기구간 분포현황 및 수익률 추이 (혼합 차트)
- **억원 단위 막대/선 차트**: 만기까지 남은 잔존 기간(3개월 이하, 6개월 이하, 1년 이하 등)에 매칭되는 금액(막대)과 구간 평균 금리(꺾은선)를 시각화.

### ④ 연도별 자산규모 및 수익률 변동 (YoY Trend)
- 과거 5개년 데이터를 기반으로 총 자산 증감(억원 단위) 및 가중평균 수익률의 중장기 추세 파악 가능.

### ⑤ 퇴직연금 개별 상품 상세 내역 테이블
- **신규일(가입일) 열 반영**: 엑셀 시트에서 가공한 상품의 최초 가입일을 테이블에 명확히 표기.
- **당해년도 만기 상품만 보기 필터**: 원클릭 토글 버튼을 통해 조회 기준일의 연도 내에 만기가 돌아오는 상품 리스트만 별도 추출 가능.
- **통합 검색**: 기관명 및 상품명 실시간 검색(초성/단어 필터링).

### ⑥ 계산 상세 모달 & 데이터 정합성 점검
- **가중평균 수익률 / 예상 연이자 KPI 카드 클릭** → 계산 공식, 금융기관별·상품유형별 운용수익 내역(운용금액·평균금리·예상연이자·비중)을 모달로 표시. 전년말 스냅샷이 있으면 **기관별·상품유형별 이자수익의 전년 대비 증감(▲/▼)**을 함께 표기.
- **금리 불일치 자동 점검**: "운용 증감 비교" 섹션 상단에, 기관+상품명+만기일이 동일한(=롤오버되지 않은 같은 계좌) 상품인데 전년 대비 금리가 달라진 항목을 자동으로 찾아 경고 표시(`findRateAnomalies` in `app.js`). 확정금리형 상품은 만기일이 같으면 가입 시점 금리가 고정이므로, 금리가 다르면 상품 교체 또는 둘 중 한 해의 데이터 입력 오류를 의심할 수 있음.

## 4. 기술 스택 및 핵심 설계

- **Backend / Parser**: Python 3.9+, `openpyxl` (엑셀 데이터 클렌징 및 통합 스냅샷 JSON 빌드)
- **Frontend**: HTML5, Vanilla CSS (Glassmorphism 다크 테마 적용), JavaScript (ES6)
- **Charts**: `Chart.js` v4+, `chartjs-plugin-datalabels` v2
- **Core Script 설명**:
  - `parse_data.py`: 연도별 시트를 순회하여 헤더 행 위치를 자동으로 스캔하고 "신규일", "만기일", "금리" 데이터를 추출하는 강건한(Robust) 엑셀 파서 엔진. 실행 시 스크립트와 같은 폴더의 `data.json`을 갱신한다(경로를 다른 곳으로 바꾸면 대시보드가 갱신된 데이터를 못 읽으니 주의).
  - `app.js`: 웹 UI 컨트롤러. `smartOutsideLabels` 커스텀 Chart.js 플러그인으로 도넛/파이 차트 외곽 라벨을 겹치지 않게 배치(라벨 이동 범위는 `layout.padding`으로 확보한 캔버스 전체 여백을 사용 — 원 자체 영역인 `chartArea`로 제한하면 여백이 있는데도 불필요하게 밀리므로 주의).
  - `style.css`: 가독성을 극대화한 네이비-그레이 톤의 프리미엄 다크 테마 및 반응형 레이아웃 스타일시트. 차트 카드 내부 레이아웃(`.chart-inner-layout`)은 `flex-grow`가 없으면 부모 카드를 키워도 실제 차트 그리기 영역은 늘어나지 않으니 유의.

## 5. 실행 및 사용 방법

```bash
pip install openpyxl
```

### 2단계: 엑셀 데이터 파싱 및 JSON 갱신
```bash
python parse_data.py
```
*(성공 시 신규 데이터가 반영된 `data.json`이 생성됩니다.)*

### 3단계: 로컬 웹 서버 실행
```bash
python run_dashboard.py
```

### 4단계: 대시보드 접속
브라우저를 열고 다음 주소로 접속합니다:
👉 **[http://localhost:8000](http://localhost:8000)**

### 알려진 참고사항
- 농협 등 일부 금융기관 시트에 최초 가입일(신규일) 정보가 누락되었거나 날짜 형식이 다른 경우 파서가 `None` 처리하며, 대시보드 테이블상에는 `-` 기호로 표시됩니다.

### 6-1. 자금통합포털(`zzi_ori`) 3대 자금 업무 통합 구조

자금통합포털은 파편화되어 관리되던 자금팀의 3대 핵심 업무를 하나의 데이터베이스와 포털 UI로 통합합니다:

### 6-2. 차입금 관리 파트 및 월간 보고서 연계 방안

1. **💳 차입금 관리 파트 연계**:
   - **데이터 연동**: `차입금_관리내역.xlsx` 원본 및 `snapshot_db.py`, `group_loan_db.py`의 차입 데이터베이스(단기차입금, 장기차입금, 그룹/관계사 차입)를 포털 중앙 DB로 통합.
   - **이자비용 vs 운용수익 종합 대시보드**: 퇴직연금의 **운용 이자 수익**과 차입금의 **차입 이자 비용**을 동일 화면에서 상호 비교하여 **순이자손익(Net Interest Spread)** 분석 제공.
   - **만기 리파이낸싱 통합 알림**: 퇴직연금 상품 만기 도래와 차입금 1년 이내 만기 상환 일정을 통합 타임라인으로 시각화.

2. **📊 월간 자금보고서 파트 연계**:
   - **월간 보고서 자동 생성**: `monthly_report_db.py` 및 `report_shared.py` 모듈과 연동하여, 퇴직연금 월말 스냅샷 잔액과 차입금 월말 잔액을 자동 추출.
   - **경영진 맞춤형 KPI 보고서**: 매월 엑셀 수동 편집 없이 월간 자금 수지, 운용/차입 현황, 순차입금 추이 리포트(PDF/Excel) 자동 템플릿화.
   - **단기자금 판단(단판) 메일 자동화**: `danpan_mail.py`와 결합하여 매일/매주 자금 수시 현황 및 단기 운용 추천 내역을 자금팀 및 관계 부서에 자동 발송.

### 6-3. 포털 이식을 위한 단계별 실행 과제

| 순서 | 이식 구분 | 현재 상태 (로컬) | 자금통합포털(`zzi_ori`) 목표 | 비고 및 실행 계획 |
|---|---|---|---|---|
| 1 | **데이터베이스 통합** | JSON/SQLite 기반 파편화 저장 | Supabase PostgreSQL 단일 RDB로 통합 (`pension_snapshots`, `loan_snapshots`, `treasury_monthly`) | 엑셀 파서 결과를 API endpoint를 통해 DB로 직접 ingestion |
| 2 | **사용자 인증 & 권한** | 없음 (로컬 실행) | Supabase Auth + RLS (Row Level Security) | 열람 승인된 자금팀 및 경영진 계정만 접근 가능하도록 조치 |
| 3 | **프론트엔드 이식** | Vanilla JS + Streamlit 이원화 | React + Vite 단일 통합 대시보드 | Chart.js 및 Plotly 기반 로직을 React 컴포넌트(JSX)로 마이그레이션 |
| 4 | **AI 지원 모듈 연동** | 수동 데이터 점검 | 금리 시뮬레이션 & 만기 리파이낸싱 알림 AI Agent 도입 | 시장 금리 변동 시 차입/운용 이자 변화 시뮬레이션 기능 |

### 6-4. 데이터 보안 및 이전 시 주의사항

- **실데이터 보안 유지**: `data.json`, 차입금 엑셀 등 실 금액 데이터는 `.gitignore`를 통해 git 추적에서 철저히 제외.
- **포털 접근 권한 강화**: Cloud/Web 이식 시 RLS(Row Level Security)를 설정하여 권한 있는 사원만 접근할 수 있도록 보안 설정 적용.
- **배포 파이프라인**: 엑셀 파싱 스크립트를 관리자 전용 웹 업로드 파이프라인으로 전환하여 담당자가 웹에서 엑셀을 업로드하면 즉시 포털 DB가 갱신되도록 구축.
